# Contributing to the vatger Website

Thank you for considering contributing to the vatger website! We appreciate
your time and effort to help make the project better.

The following guidelines are intended to make contributions easier to discuss,
review, and maintain. They are guidelines rather than strict rules, so please
use your best judgment and feel free to propose improvements in a pull
request. Contributions will be reviewed before being merged.

## How to Contribute

There are many ways to contribute to this project, including:

- Creating or improving documentation
- Fixing a bug
- Implementing a new feature
- Improving accessibility, usability, or performance
- Discussing potential improvements
- Reporting a bug
- Submitting feedback

## Getting Started

To get started, [create an issue](https://github.com/vatger/homepage/issues) to
describe the change or problem you would like to discuss. This allows the
maintainers and community to provide feedback before you spend time coding.

For local development instructions, see the [Installation section in the
README](README.md#installation). Before submitting changes, make sure the
application can be built and the relevant tests and formatting checks pass.

## Pull Request Process

1. [Fork](https://help.github.com/en/github/getting-started-with-github/fork-a-repo)
   the repository and create a focused branch for your change.
2. Make your changes to the codebase.
3. Update the [README.md](README.md) with relevant documentation when the
   behavior or setup process changes.
4. Run the applicable checks, including `npm run format:check`, `npm run build`,
   and `php artisan test`.
5. Submit a pull request describing what changed, why it changed, and how it
   was tested.

Please keep pull requests focused and include screenshots or other helpful
context for visual or user-facing changes.
